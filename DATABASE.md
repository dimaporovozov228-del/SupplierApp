# Схема базы SupplierApp

Файл `SupplierApp.mdb` имеет формат Access 2000 / Jet 4.0.
Все перечисленные поля обязательные; идентификаторы создаются счетчиками.

## Users

| Поле | Тип Access | Назначение |
| --- | --- | --- |
| UserId | COUNTER, PK | Идентификатор пользователя |
| UserName | TEXT(50), UNIQUE | Нормализованный логин |
| FullName | TEXT(100) | Отображаемое имя |
| PasswordSalt | TEXT(24) | Base64 соли из 16 байтов |
| PasswordHash | TEXT(44) | Base64 результата PBKDF2, 32 байта |
| HashIterations | LONG | Число итераций, первоначально 600000 |
| CreatedAt | DATETIME | Дата и время регистрации |

Логин нормализуется удалением внешних пробелов и переводом в нижний регистр.
При регистрации принимаются 3–50 латинских букв, цифр и символов `_ . -`.
Пароль имеет длину 8–128 символов и не обрезается методом Trim.

## Products

| Поле | Тип Access | Назначение |
| --- | --- | --- |
| ProductId | COUNTER, PK | Идентификатор товара |
| ProductName | TEXT(100) | Наименование |
| Unit | TEXT(10) | Единица измерения, кг |
| UnitPrice | CURRENCY | Цена за единицу |
| IsActive | YESNO | Показывать ли товар в каталоге |

| Начальный товар | Цена за кг, руб. |
| --- | ---: |
| Помидоры | 180,00 |
| Огурцы | 150,00 |
| Картофель | 60,00 |
| Яблоки | 120,00 |
| Апельсины | 160,00 |
| Бананы | 140,00 |

## Orders

Одна запись соответствует заказу одного вида товара, как в исходном проекте.
Корзина из нескольких позиций в эту версию не добавляется.

| Поле | Тип Access | Назначение |
| --- | --- | --- |
| OrderId | COUNTER, PK | Номер заказа |
| UserId | LONG, FK | Покупатель, ссылка на Users |
| ProductId | LONG, FK | Товар, ссылка на Products |
| Quantity | DECIMAL(18,3) | Количество в кг |
| UnitPrice | CURRENCY | Цена на момент оформления |
| DeliveryAddress | TEXT(255) | Адрес доставки |
| CreatedAt | DATETIME | Местные дата и время оформления |
| OrderStatus | TEXT(20) | Первоначально «Новый» |

Сумма не дублируется в таблице: запрос истории вычисляет
`Round(Quantity * UnitPrice, 2)`. Форма использует то же округление к ближайшему
четному при точном попадании на середину. Это предотвращает рассогласование суммы
и исходных количества и цены.

Приложение принимает количество больше нуля и не больше 10000 кг, не более трех
знаков после запятой, адрес после Trim длиной 5–255 символов. Перед записью
повторно проверяются активность товара и соответствие его текущей цены показанной.
Проверка диапазонов выполняется в коде; при прямом изменении Access она не заменяет
проверку данных оператором. База обеспечивает типы, обязательность, уникальность
логина и внешние ключи.

## Связи и операции

| Родитель | Дочернее поле | Кратность | Правило |
| --- | --- | --- | --- |
| Users.UserId | Orders.UserId | 1 : N | Без каскадного удаления |
| Products.ProductId | Orders.ProductId | 1 : N | Без каскадного удаления |

Создание пользователя и заказа выполняется в транзакции. После `INSERT`
номер читается через `SELECT @@IDENTITY` в том же соединении и транзакции.
Только после успешного Commit форма сообщает о сохранении. История выбирается
параметризованным условием `WHERE o.[UserId] = ?`.

Основные методы находятся в `SupplierApp\AppDatabase.cs`: `CheckConnection`,
`Authenticate`, `Register`, `GetProducts`, `CreateOrder`, `GetOrders`.
